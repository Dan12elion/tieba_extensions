# 成分关键词规则：格式与排查

「成分」规则用来回答一个问题：**页面上这个人，像不像某一类人**。规则表就是你在设置面板里逐行写的纯文本，脚本照着它去读每个人的「关注的吧」和「发过的帖」，命中的话在用户名旁（「查询」按钮右边）挂一个彩色标记。标记的颜色由规则名算出来，同一条规则在哪个页面都是同一个颜色。鼠标停在标记上能看到命中的原因；点它直接打开这个人的「成分」页签，里面列着命中了哪条规则、命中了哪个词、原文片段是什么。

规则每行一条，用 `|` 分成最多六段：

```
名称 | 发帖关键词 | 关注的吧关键词 | 排除关键词 | 直接命中名单 | 发帖所在吧关键词
```

后四段可以省略；关键词之间用逗号分隔（中英文逗号都行，分号也认）。**关键词按「包含」匹配，大小写不敏感**。

上面这段格式提示就写在设置面板的规则框里，设置面板还带「填入示例（二游大战）」和「清空规则」两个按钮。

---

## 1. 逐字段说明

| 段 | 字段名 | 含义 | 匹配对象 | 可否省略 | 示例 |
|---|---|---|---|---|---|
| 1 | 名称 | 规则名，也是标记上显示的文字；可以带 emoji | —— | 不可省（空的整行忽略） | `🎮原神` |
| 2 | 发帖关键词 | 他发过的内容里有没有这些词 | 该用户主题帖 / 回复 / 楼中楼的「标题 + 正文摘要」 | 可省 | `原神,芙宁娜` |
| 3 | 关注的吧关键词 | 他**关注了**哪些吧 | 该用户关注的吧名（`getLikeForum`，拿不到时走隐藏关注恢复通道） | 可省 | `原神吧,米哈游吧` |
| 4 | 排除关键词 | 命中就把这条证据作废，用来压住玩梗误伤 | 与第 2、3 段同样的文本上 | 可省 | `原神怎么你了` |
| 5 | 直接命中名单 | 指定贴吧号或内部用户 ID，指名道姓 | 该用户的贴吧号（`uid`）与内部 ID（`user_id`） | 可省 | `1234567890` |
| 6 | 发帖所在吧关键词 | 他**实际在哪个吧发过言** | 他发过的帖所属的吧名 | 可省 | `拼多多,淘宝` |

字段读写顺序值得单独说一句：规则文本里的列序就是第 1~6 段这个顺序，代码按位置取值。第 6 段之所以加在最后，是为了不动老规则（5 段）的列序。

**第 3 段和第 6 段是两回事**：第 3 段看的是他关注了什么（关注是主动行为，但很多人关注一堆吧却从不说话），第 6 段看他确实在哪儿发过帖。

## 2. 可以照抄的示例

把下面整段粘进设置面板的规则框就能用（设置面板的「填入示例（二游大战）」按钮填的是另一套更完整的清单，写法相同）。关键词用逗号分隔，**不要用空格分隔**。

```
# 每行都是：名称 | 发帖关键词 | 关注的吧关键词 | 排除关键词 | 直接命中名单 | 发帖所在吧关键词
🎮原神 | 原神,芙宁娜,米哈游 | 原神吧,米哈游吧 | 原神怎么你了
🎁抽奖 | 互动抽奖,转发本条动态 | 抽奖吧
🛒带货 | | | | | 拼多多,淘宝
⚠️示例名单 | | | | 1234567890
🕹️玩梗 | 米哈游 | | 崩坏,星穹铁道
📌只发原神吧 | | | | | 原神吧
🤝某个人 | | | | 874540992
```

逐行解释：

| 行 | 它会命中什么 |
|---|---|
| `# 每行都是…` | `#` 开头是注释行，整行忽略。注释不占段位，写在任何位置都不影响别的行。 |
| `🎮原神` | 三段写法。发帖标题或正文摘要里出现「原神」「芙宁娜」「米哈游」之一，**或者**他的关注吧名里有「原神吧」「米哈游吧」之一，就算命中。但如果命中的那段文本里同时出现「原神怎么你了」，这条证据作废（见第 4 节的坑）。 |
| `🎁抽奖` | 两段写法，没有排除词也没有名单。发帖里出现「互动抽奖」或「转发本条动态」，或者关注了吧名里含「抽奖吧」的人。 |
| `🛒带货` | 前四段留空，只用第 6 段：他发过的帖所属吧名里含「拼多多」或「淘宝」。注意这里**不看**他关注了什么，只认实际发过言的吧。 |
| `⚠️示例名单` | 只写了名称和名单：贴吧号或内部 ID 命中 `1234567890` 就命中，**不读关注吧、也不读发帖**，一个请求都不发。适合盯某几个已知账号。 |
| `🕹️玩梗` | 带排除词的写法。发帖里有「米哈游」才算候选，但那段文本里出现「崩坏」或「星穹铁道」就作废——用来滤掉讨论别的作品的帖子。 |
| `📌只发原神吧` | 与 `🛒带货` 同为只用第 6 段。他发过的主帖/回复只要在「原神吧」里就算命中，不看他关注了哪些吧。 |
| `🤝某个人` | 与 `⚠️示例名单` 同型，换成一个内部 ID：按 ID 直接命中，不取任何数据。 |

## 3. 常见坑

- **关键词绝不按空格切分。** 分隔符只有逗号（以及分号），空格是关键词的一部分。所以 `互动抽奖 #原神` 是一个完整的词，写成这样才找得到它；如果你想要「互动抽奖」和「原神」两个词，必须写成 `互动抽奖,原神`。（参考脚本里就有带空格的词，所以这一条是刻意的。）
- **`|` 段数写多了：多出来的部分被静默忽略。** 一行只认前 6 段，第 7 段及之后既不算关键词也不报错。反过来，**末尾多一个 `|` 没关系**：最后一段会是空字符串，等同于省略该段，规则照常生效。
- **排除词并不是只排除那一条证据，而是作废整条证据。** 具体来说：关注吧匹配时逐个吧名过排除词，命中的那个吧不算数；发帖匹配时，只要那条帖子的「标题 + 正文摘要」里出现排除词，整条帖子直接跳过，**哪怕同一个关键词在别处也命中过**。规则本身不会被删掉——它只是拿不到被排除的那种证据。
- **只有名称、没有任何条件（第 2/3/5/6 段都空）的行会被丢掉。** 只写了名称和排除词也一样会被丢掉：排除词不构成命中条件。
- **同名规则只保留第一条**（名称比较同样不区分大小写）。被丢掉的那条不会参与匹配，也不会提示。
- **回复与楼中楼只是弱证据。** 主题帖、关注的吧、名单都算强证据；同一条规则如果只靠回复或楼中楼命中，标记会淡一些，tooltip 里写「（证据较弱，可能是误判）」，面板里写「证据较弱，可能是误判」。回复里出现某个词很可能只是在讨论或玩梗，这是设计上的取舍，不是 bug。
- **隐藏了关注贴吧的用户也参与判定。** 主接口拿不到关注吧时，脚本会从资料接口自带的关注贴吧字段、以及「吧内等级 → 吧名」的分组里恢复一部分吧名参与匹配；面板会写明「其中 N 个来自隐藏关注贴吧的恢复」。恢复出来的列表可能不完整，这是贴吧自身的限制。另外，如果主接口抛错（不等于「没有关注的吧」），回退通道也会照走。
- **发帖匹配前 N 页，每页 60 条（默认 1 页）。** 主题帖与回复**各**按设置项「成分检测每路翻几页」取数，默认各 1 页 = 各最多 60 条；再往前的帖子不参与匹配。所以「他早就发过这个词」可能查不到，这是有意的成本控制——需要覆盖更早的帖子就把页数调大（见下节）。
- **同一个词同时写在关键词与排除词里，等于自我否决。** 那条证据永远会被排除词刷掉；设置面板会在规则表下面按行号提示这种情况。
- **同一规则的多条证据会合并成一个标记**，不会出现两个一样的徽章；面板里把每条原因都列出来。
- **没有命中、但数据没拿到的，是「证据不足」。** 对方把发帖记录设为私密、或者取数失败时，页面上会出现一个灰色的「证据不足」标记（点开仍进「成分」页签，里面写着缺的是什么）。它**不等于**"没有命中"。

## 4. 请求成本与开关

- **规则表为空时零请求**：脚本一个请求都不发（默认装上就是这个状态）。此时「成分」页签会直接提示还没配置规则。
- **只写名单（第 5 段）的规则零请求**：名单是靠贴吧号和内部 ID 直接比对的，不需要读关注吧或发帖。
- **每个用户至少 3 个请求**：关注的吧 + 主题帖第 1 页 + 回复第 1 页。而且按规则里实际用到的字段减免——没有任何规则用到第 2/6 段，就不取发帖；没有任何规则用到第 3 段，就不取关注吧。
- **页数由「成分检测每路翻几页」决定**（默认 1，可填 1~10）：主题帖与回复各按这个页数取数，所以每个用户最多 `1 + 2 × 页数` 个请求（关注吧 1 个 + 两路 feed 各 N 个）。某一页取到 0 条会**提前停下**，不浪费请求。
- **每页人数上限**：设置项「每页最多检测人数」，默认 20（可填 1~200）。同一页里登记的用户数达到上限后，多出来的不再排队。
- **自动检测开关**：设置项「页面自动检测」，关掉后只贴已有缓存，不再为新用户排队；面板里手动点开某人的「成分」页签仍会正常检测。
- **结果进缓存**：同一个用户在同一份规则下只查一次。缓存默认 3 天过期（设置项「成分缓存天数」，可填 1~365）。
- **改规则会让缓存自动失效**：缓存里存着当前规则表的指纹，你一动规则表，旧结论立刻作废，不需要手动清缓存。想立刻重查某个人，用「成分」页签里的「重新检测」，或脚本菜单的「eztb：重新检测本页用户」；想全清就用菜单里的「eztb：清空成分缓存」。
- 还需要先设置 BDUSS：没设的话成分检测不会工作（会提示去设置）。

## 5. 一条规则没生效，怎么排查

按这个顺序走，基本能定位到原因：

0. **先看设置面板里规则表下面的那行提示。** 1.9.0 起解析器会**按行号**报问题：只有名称没有条件、与第 N 行同名只保留第一条、关键词里混了空格、同一个词既是关键词又是排除词、段数超过 6 段——这些都会被指出来。很多"没生效"在这一步就有答案。

1. **先看标记有没有出现。** 标记只会在**命中**时插入——没命中就没有任何东西，这不是故障。顺便确认三件事：规则表不是空的、已经设置了 BDUSS、设置里的「页面自动检测」是「开启」。
2. **用脚本菜单的「eztb：诊断当前页面」复制报告。** 重点看这两块：`[已注入按钮]` 是不是 0（是 0 说明扫描器没认到这个页面上的用户，跟规则无关）；`页面上的用户主页链接（按 class 统计）` 里出现的 class 有没有被扫描器覆盖。报告里还有 `在飞请求`、`请求熔断状态`、`存储写入失败记录`、`最近的日志`，能看出请求是不是被限速队列或熔断挡住了、缓存是不是根本没写进去。
3. **打开这个人的「成分」页签看统计。** 面板会打印一行「已检查：关注的吧 N 个（其中 M 个来自隐藏关注贴吧的恢复）· 主题帖 N 条 · 回复 N 条」，末尾带「（来自缓存）」（如果读的是缓存）。对照它想：你写的关键词到底有没有可匹配的对象——比如只写了关注吧关键词、但这里「关注的吧 0 个」，那就不是规则的问题，是数据没取到。
4. **看有没有「部分数据没取到」那一行。** 面板会把失败的数据源和原因写出来（关注的吧 / 主题帖 / 回复 三路各自独立，局部失败不影响其余部分），诊断报告的日志里也会有 `成分检测失败：` 这类记录。如果三路都失败（对方设了隐私、BDUSS 失效），标记就不会出现。
5. **回到规则本身检查这三件事**：排除词是不是把候选帖子全刷掉了（排除词命中是**整条**证据作废）；`|` 的位置是不是错了一格——最常见的错误是把关键词写到了「直接命中名单」那一段；以及关键词里是不是混进了空格（空格不会被当成分隔符）。
6. **最后注意弱证据和样本范围。** 只靠回复命中的规则，标记是淡的、面板写「证据较弱，可能是误判」，容易被当成「没生效」；另外发帖只匹配第 1 页，更早的帖子根本不在匹配范围里。
